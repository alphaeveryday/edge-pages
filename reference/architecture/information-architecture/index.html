    EDGE — Information Architecture¶

    원본: EDGE_아키텍처_v0_2.pptx — Slide 1 (Information Architecture)

    [설계 뷰] 콘솔 정보구조의 논리 개요다. 현행 콘솔 화면·메뉴의 권위는 SSOT super-admin-console.md·tenant-console.md에 있다. 충돌 시 SSOT 우선.

    이 문서는 콘솔 재설계 목표이며 console-ia/로 전진 완료됐다(Audit Log·Admin Activity Log 메뉴 제거, 감사=DB 보존). 현행 콘솔 메뉴의 권위는 console-ia/다 (system-architecture.md 전진 예정 축).

    개요¶

    EDGE의 정보 구조는 최상위 EDGE 아래 세 갈래로 분기한다.

    1. EDGE 위젯 — 증권사 서비스에 임베드되는 위젯. 종목별 가격 변동 설명을 노출
    2. 고객사 운영 콘솔 — 로그인 후 진입. 증권사(테넌트) 담당자가 설명 제공·검수·기준을 관리
    3. 슈퍼 어드민 콘솔 — 로그인 후 진입. EDGE 운영자가 테넌트와 분석 파이프라인을 관리

    구조 요약¶

    영역 대상 사용자 핵심 기능
    EDGE 위젯 증권사 최종 고객 (투자자) 종목별 가격 변동 설명 열람
    고객사 운영 콘솔 증권사 담당자 대시보드, 설명 관리, 검수, 점검 기준 관리, 환경 설정
    슈퍼 어드민 콘솔 EDGE 운영자 테넌트 관리(목록·생성), 가격 변동 분석 관리(수집 상태·분석 목록)

    비고¶

    • 설명의 상태 라이프사이클(자동 제공 → 검수 대기 → 점검 차단 / 검수 반려 / 제공 중단)이 대시보드·목록 필터·상세 액션에 일관되게 반영되어 있음
    • 검수로 이관 / 승인 / 반려 등 액션 노드는 화면이 아닌 기능(operation) 단위
